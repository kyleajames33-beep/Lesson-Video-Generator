# Old engine ideas audit

Date: 16 October 2026. Read-only audit of the slide engine (`src/LessonVideo.tsx`, `src/slides/`, `src/slides/diagrams/`, `src/animations/`, root `public/assets/`) for anything worth reusing in the explainer engine (`src/explainer/`). Nothing was edited, rendered or committed. Findings come from code headers, props and logic, not from playback. Judge any port at playback speed before selection.

Companion: `docs/production/claude-pm/library-inventory.md` (11 October, header-level list). This file goes deeper on teaching value, correctness and portability for the next topics in `docs/production/claude-pm/pre-design/`.

## Summary

- The old engine is a rich idea bank. Its best kinds are **model-driven**: the numbers on screen are computed from the same state that moves the particles (Q from particle counts, ratios from the Punnett grid, mutation labels from a real codon table, pH from a charge balance). That discipline is worth importing more than any drawing.
- Upcoming Chemistry topics C10 to C15 already have a near-complete old set in `kinds/chem-y12-m5/` (colourimetry, Ka/Kb, dissolution energy, cycad leaching, net ionic, Ksp, mixing and dilution, common ion, Qsp gauge). Several use the exact worked numbers of the site pages (AgCl 1.8 × 10⁻¹⁰; 50 mL + 50 mL of 2.0 × 10⁻³ mol L⁻¹; [Ag⁺] = 1.8 × 10⁻⁹ in 0.10 mol L⁻¹ NaCl).
- Upcoming Biology B7 to B12 and Module 6 Biology are well covered in `kinds/bio-y12-m5/`, `kinds/bio-y12-m6/` and `kinds/bio-y12-m8/` (computed crosses, sex linkage, heterozygote comparison, transcription, translation, codon mutations, Wright-Fisher drift, SNP reads, association versus causation).
- Module 6 Chemistry (acid/base) has strong computed kinds in `kinds/chem-y12-m6/` (pH scale with countable tenfold steps, buffers, indicators, titration curves).
- The **look** must not be copied: stone plinths, glossy marbles and grey-glow icons conflict with the paper, ink and painted-plate system. Port logic and teaching ideas; redraw in kit style; use the new `m5x-*` plates as organism and apparatus anchors.
- Gaps the old engine does not fill: a data-driven pedigree generator, gel electrophoresis or STR bands, a codon-table visual.
- No current or planned Module 5 explainer video depends on the old engine. Six older Year 11 public videos and the release gate tooling do. See "Dependency answer".

## Do not copy

- **The diorama look.** Stone plinths, glossy marbles, `DioramaPlinth`, `GlossDefs` and the grey-glow root images (`public/assets/Beaker.png`, `dna-helix.png` and similar: glossy 3D icons on a grey vignette, not transparent paper plates). They break the one-visual-system rule.
- **TranslationDiagram anticodons** (`kinds/bio-y12-m5/TranslationDiagram.tsx`): the anticodon is printed as a plain complement in codon order with no 3′/5′ labels. The B8 pre-design names this exact trap. Label 3′→5′ against the codon, or reverse it 5′→3′.
- **ColourimetryDiagram gaps** (`kinds/chem-y12-m5/ColourimetryDiagram.tsx`): forces the calibration line through the origin, has no dilution step before the ICE table and does not show that standards use Fe³⁺ in large excess. The C10 pre-design requires all three distinctions.
- **KaKbDiagram scope** (`kinds/chem-y12-m5/KaKbDiagram.tsx`): its main beat is Ka × Kb = Kw, which C11 leaves to Module 6. For C11 use only the expression halves. The seesaw reads as "one goes up by what the other loses"; it is only literal on a log scale (pKa + pKb = 14 at 25 °C), so label it that way in Module 6 or drop it.
- **QGauge `qsp` mode**: Qsp is the product of ion counts with no volume and no stoichiometric powers. Acceptable as a qualitative 1:1 picture only; never for CaF₂ or Ag₂CrO₄.
- **HeterozygoteDiagram co-dominance flower**: alternating red and white petals can read as a spotted or mosaic flower. Use roan cattle (each hair one colour) or ABO antigens.
- **FoldDiagram**: implies one amino-acid change always closes the pocket. Pair it with silent and conservative changes (CodonsDiagram computes silent) or state "can".
- **TitrationCurveDiagram legacy mode** and **HeatLedgerDiagram for acid strength**: both headers record that legacy labels or uses were narrowed after review. Use only `reviewedAnalytical` output and the scoped heat-ledger modes.
- **PedigreeChartDiagram**: one fixed autosomal-dominant family. Consistent with AD, but it cannot teach the B11 skill of testing every mode against named individuals.
- **PunnettSquareDiagram**: monohybrid 2 × 2 only and coupled to old scene JSON; use CrossDiagram logic instead.
- **Empty or stale**: `LottieDiagram` (lottie folder empty), `sceneSync.ts`, dark-palette docs flagged historical in `REPO-GUIDE.md`.

## Dependency answer

- **Module 5 explainer videos: no dependency.** Every Module 5 upload in `docs/production/claude-pm/youtube/wave1` to `wave4` was rendered from `out/explainer/Explainer-*.mp4`. `src/explainer/` imports nothing from `src/slides/`, `src/animations/` or `src/LessonVideo.tsx`; its only outside import is `src/styles/tokens.ts` (kit colours and fonts). `scripts/render-explainer.mjs` bundles a generated entry that registers only the explainer composition.
- **The old engine is still live elsewhere:**
  - Six older public Year 11 videos (Mole Concept Part A, molar mass and the four calculation lessons per `REPO-GUIDE.md`) were built on `LessonVideo` (the calculation packages through `src/dev/release-entry.tsx`; Part A's exact render path was not traced). Their frozen release inputs and evidence reference this code.
  - `scripts/render-release.mjs` and the release gate scripts render `Lesson-release` through `LessonVideo`.
  - `src/Root.tsx` (Remotion Studio, `npm start`) imports `LessonVideo` and registers all 308 lesson compositions beside the explainers.
  - `src/prototypes/`, `src/dev/` showcases and the `test:source` suite (component-output tests) import old diagram kinds and the `*-models.mjs` validators.
  - `REPO-GUIDE.md` (10 to 11 October) still lists `src/slides/` and `LessonVideo` as Core and predates the explainer switch.
- **Planned work:** no pre-design pack in `docs/production/claude-pm/pre-design/` plans to use the old engine. The 11 October runner motion pilot used LessonVideo, but the published B2b came from the explainer.

## Archiving recommendation

1. **Do not delete or move yet.** Public releases and the release gate depend on it, and archiving would break Studio, prototypes and tests.
2. **Freeze it.** Treat `src/LessonVideo.tsx`, `src/slides/` and `src/animations/` as read-only legacy: no new lessons, no restyles. Update `REPO-GUIDE.md` so the explainer is "Core" and the slide engine is "Legacy, frozen".
3. **Port first, then archive.** Lift the pure utilities into the explainer (suggested `src/explainer/models/`): `codonToAA`/`translate`, cross and ratio logic, `wrightFisher`, `solvePH`/`phColor`, `exchangeSim`, `lcEqSim`, the Q ÷ (Q + K) gauge mapping, `bounce`/`hash01`, kbKit maths text, plus the doodle primitives the kit lacks. Copy, do not import, so the explainer stays independent.
4. **Keep shared foundations.** `src/styles/tokens.ts` is used by both engines; it must stay outside any archive.
5. **Archive later as a tagged snapshot.** Once the Year 11 videos are either superseded or their evidence is preserved by a git tag plus the existing media release, move the old engine to an archive branch or `archive/` with a tag, remove its compositions from `src/Root.tsx`, and point the release gate at the explainer pipeline. This step needs owner approval.
