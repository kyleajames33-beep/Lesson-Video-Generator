## Decisions

- **Learner question (placeholder rewritten; open decision 3).** Route placeholder: "How can I processing data and information in a defensible physics investigation?" Rewritten as one plain causal question: "Why must raw readings be converted, organised and sourced before they count as evidence?" The answer, built in order: raw readings come in the instrument's units, and substituting them unconverted gives a wrong number (1, 2); converting to SI base units first, then sense-checking in a familiar unit, catches it (2, 3); processed quantities turn readings into what the model needs (4); a spreadsheet applies one process to every row, so one hand check protects every row (5, 6); each representation does a job, so the choice follows the purpose (7, 8); a source mixes what you need with what you don't (9); naming the source lets a reader check it (10).
- **The hook (a surprise from v24's own numbers).** 5.00 ÷ 47.88 = 0.104: "Is the trolley really crawling along at 0.1 metres per second?" 3 s prediction with chips "yes", "no: faster", "no: slower". The true speed is 1.044 m s⁻¹: centimetres per millisecond is ten times a metre per second (author note a). The reading, flag and timing are v24's exactly (`phys-y11-fa1-v24.md` author note b), tagged "from an incline investigation (illustrative data)".
- **Conversions (`ci21267953`).** Rule taught: convert every value to metres, kilograms and seconds before substituting, and write units in every line. Meanings given in plain words: centi a hundredth (10⁻²), milli a thousandth (10⁻³), kilo a thousand (10³). Only these three prefixes are used; fa0-v05 owns the full prefix list (grey tag "more prefixes: Analysing data"). The km h⁻¹ conversion is derived, not stated: 1 km h⁻¹ = 1000 m ÷ 3600 s, so m s⁻¹ × 3.6 = km h⁻¹ (FA1 root decision 3 units). Sense check: 1.044 × 3.6 = 3.76, "about 3.8 km h⁻¹, a slow walk" (typical walking pace is about 5 km h⁻¹).
- **Processed column (v10's falling ball).** Heights 0.200 to 1.000 m and times 0.207 to 0.458 s (v10 run 1, author note a there); t² column 0.0428 to 0.2098 s². The model s = ½gt² is recalled as "says distance should be proportional to time squared" (its physics is v09 and v10's). Table rules: independent variable first; headings "quantity (unit)" so cells hold plain numbers; raw columns then processed; each column to a consistent number of decimal places (said on screen only; significant figures belong to fa0-v05).
- **Spreadsheet (`ci0fca96de`: spreadsheets).** One formula filled down, e.g. "=B2^2" for t². The trap (prediction 2, 3 s): "=SIN(A2)" with 30 in A2 gives −0.988, because spreadsheet trigonometry works in radians; "=SIN(RADIANS(A2))" gives 0.500. The lesson: a formula repeats one process exactly, so one hand check of the first row protects every row. Spreadsheet function names are written as in common spreadsheet software (tag "most spreadsheets"; no brand named).
- **Representations by purpose (`ci0fca96de`).** Table (keeps exact values), graph (shows the trend: s against t² straight), labelled diagram (shows the set-up: v10's stand, magnet, ball and trapdoor), model (s = ½gt² says what the pattern should be, so we can compare). "Model" glossed as "a simplified description, often an equation, that predicts a pattern". Keys: when two data sets share axes (a smooth and a rougher track's a against sin θ lines, v24 scene 9), a key says which is which.
- **Graph conventions with an honest exception.** "Usually the independent variable goes across and the dependent variable up." v10 plots s (its independent variable) up against t² so the gradient is ½g; the narration says once that physicists sometimes swap the axes on purpose so the gradient means something, and that a report then says so. This keeps v10 and v15 consistent with the rule.
