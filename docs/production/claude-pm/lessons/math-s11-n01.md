### 1. hook: dots and lines
> Here's Australia's flight map from last time, with the clocks taken away. Seven cities, and ten routes joining them. Notice what's left. It doesn't matter how far apart the cities sit on the page, or which way the lines point. What matters is which cities are joined. That's the idea behind a network, one of the most useful pictures in maths. Airlines, map apps and phone companies all work with pictures like this. So what is a network, and where do networks show up in real **life**?

### 2. vertices and edges
> A network is a collection of objects joined by connections. Each object is drawn as a dot, called a vertex. More than one are called vertices. Each connection is drawn as a line between two vertices, called an edge. In the flight network, each city is a vertex, and each route is an edge. Count them. Seven vertices and ten **edges**. An edge always joins exactly two vertices, and it only says those two are connected. How long a line is drawn doesn't matter at all. You can fly straight from Perth to Sydney, so there's an edge. You can't fly straight from Hobart to Darwin in this network, so there's no edge. But you can still get there by changing planes, moving from vertex to vertex along the edges. Hobart to Melbourne, Melbourne to Adelaide, Adelaide to **Darwin**.

Visual: stage change: the flight network (as left by scene 1) centred and enlarged (1,200 px). On "drawn as a dot" one dot enlarges with tag "vertex" (hand tag "dots: vertices"); on "vertices" all dots tag "vertices". On "called an edge" one line thickens with tag "edge" (hand tag "lines: edges"). ### 3. the same network, a different drawing
> Here's the surprise. Watch the dots move. Perth slides to the right, Hobart floats to the top, and the lines stretch and bend to follow. It looks completely different, but every city is still joined to exactly the same cities as before. So it's the same **network**. A network only records what's connected to what. Distances, compass directions and the shapes of roads are left out, unless we write them on. That's why a network diagram usually isn't drawn to scale. That's exactly what a train map does. It squashes and straightens the real tracks, because a passenger only needs to know which stations connect, and in what order. Two drawings show the same network whenever they have the same vertices joined by the same edges, even if the lines **cross**.

Visual: stage change (simulation 1): the flight network at the left; a connection list at the right, 36 px: "Perth: Adelaide, Melbourne, Sydney", "Darwin: Adelaide, Brisbane", "Adelaide: Perth, Darwin, Melbourne, Sydney", and so on for all seven. On "cross" the flight network rearranges once more so two edges cross, and the list still ticks.

### 4. networks all around us
> Once you start looking, networks are everywhere. Mobile phone towers pass signals to each other. Each tower is a vertex, and each link between two towers is an edge. A rail trail for bikes has junctions and paths. The junctions are vertices, and the paths between them are edges. A town's water pipes join the reservoir, the pumping stations and the streets. A delivery van has a list of stops, and the roads between stops are the edges. A school's classrooms and corridors, the stops on a bus route, even the links between web pages, it's the same idea. Even a social media app is a network. Each account is a vertex, and each connection between two accounts is an **edge**. The trick is always the same question. What are the objects, and what joins them? Answer that, and you can draw the network.

### 5. what networks help us decide
> So why bother drawing them? Because a network turns a messy real situation into a picture we can reason about. Here are four questions networks help answer. First, is everything still connected if one link fails? Say storms close the Sydney to Brisbane route. Take that edge away. Can you still get from Sydney to Brisbane? Yes, by going Sydney, Adelaide, Darwin, **Brisbane**. Engineers ask exactly this about power lines and phone links, so that one failure doesn't cut a whole town off. Second, which place is best connected? Adelaide, Melbourne and Sydney each join four others, so they make good hubs. Third, what's the shortest or quickest route between two places? And fourth, what's the cheapest way to link every place, like laying fibre to every tower? We'll answer each of those in this strand, one at a **time**.

Visual: stage change (simulation 2): the flight network (tidy drawing) at the left; a list of four questions at the right, 40 px, lighting in turn: "1. Still connected?", "2. Best connected?", "3. Shortest route?", "4. Cheapest way to link everything?". On "storms close" a small coded storm icon over the Sydney-Brisbane edge; the edge fades to a violet dash. On "Can you still get" a search glow spreads from Sydney along the edges; on "Brisbane" (bold) the route Sydney → Adelaide → Darwin → Brisbane lights teal, row "Sydney → Adelaide → Darwin → Brisbane: still connected" (framed green), hand tag "still connected". On "best connected" Adelaide, Melbourne and Sydney enlarge, each with four edges glowing and a chip "4 each" (grey chip "n02: degree"). On "shortest" chip "n06" beside question 3; on "cheapest way" chip "n05" beside question 4, and a faint tree of edges flashes over the network. On "time" the four questions tick.

### 6. drawing a network from a description
> Let's draw one from words. A rail trail has five junctions, A, B, C, D and E. Paths join A and B, A and C, B and D, C and D, C and E, and D and E. Always start with the vertices. Draw five dots and label them. Then add the edges one at a time, ticking each one off as you go. A to B, A to C, B to D, C to D, C to E, D to E. That's five vertices and six **edges**. Count again at the end. Six paths in the description, six lines on the page, so nothing's missing. Where you put the dots is up to you. Spread them out, so the lines don't cross more than they need **to**.

Visual: stage change (simulation 3): a drawing board. Task strip, 44 px: "Rail trail: junctions A, B, C, D, E. Paths: A-B, A-C, B-D, C-D, C-E, D-E." On "start with the vertices" five blue dots drop and label (hand tag "vertices first"). On "one at a time" each listed path ticks in the strip as its amber edge draws; on "edges" (bold) row "5 vertices, 6 edges" (framed green). On "Spread them out" the dots nudge apart so no lines cross; on "to" a small ghost of a tangled version beside it fades.
